# Source audit

Audit date: 2026-10-10 (Asia/Shanghai). These are engineering claims. Static frontend code establishes the client contract, not server acceptance or live platform compatibility. No private browser data, school records, or logs are included.

| Claim | Verdict and evidence | Remaining limit |
| --- | --- | --- |
| Manual login uses an isolated persistent browser profile; ordinary browser login is separate | **CONFIRMED**: `bin/goodnight.mjs` login flow and `src/browser.mjs`; [Playwright persistent context](https://playwright.dev/docs/api/class-browsertype#browser-type-launch-persistent-context) | A real user must complete authentication; server expiry is unknown |
| Real location is requested as GCJ-02 through `uni.getLocation`, then the configured same-origin frontend export | **CONFIRMED** implementation in `src/adapters/uestc.mjs`. Current [student page bundle](https://jzsz.uestc.edu.cn/daily-checkin-h5/assets/pages-student-report-today-home-index.CNkaaYrP.js) imports `bk` as its locator and requests `gcj02`; [main module](https://jzsz.uestc.edu.cn/daily-checkin-h5/assets/index-C6QmvmXo.js) exports `sy as bk` | Coordinate system is requested, not independently measured; bundle names/exports may change |
| Endpoint names, report/check-in bodies and dorm circles follow the observed client | **CONFIRMED** static contract: [student API module](https://jzsz.uestc.edu.cn/daily-checkin-h5/assets/student.B-7kz2Ar.js) lists endpoints; student page sends latitude/longitude/reverseGeocode/clientTime/userAgent for check-in, and gpsAccuracyMeter/coordinateSystemCode for report; reads radiusMeter circles | Live acceptance of the new adapter remains **UNVERIFIABLE** from static code alone. Diagnostic fields beyond known accuracy are omitted |
| Unknown POST outcomes cannot repeat or authorize fallback | **CONFIRMED** `src/runner.mjs`, `src/store.mjs`, `test/core.test.mjs`: per-operation atomic claim precedes POST; unknown outcome only reconciles. Check-in fallback after a POST requires explicit code 4001 with no contradictory success plus fresh current-day PENDING | Code 4001 is a conservative allowlist derived from the original probes; public client code does not document all server error codes. Other codes stop without fallback |
| Check-in and report saved-record verification differ | **CONFIRMED** `src/policy.mjs` and runner tests: check-in requires date + CHECKED_IN; report requires date + STUDENT_REPORTED + type + keyword + exact remark. Mismatching saved report is unknown | Other terminal records are reported as already_done, without claiming this client verified its own submission |
| Blank reason selects the user-requested default; custom reason is 10–200 UTF-16 units | **CONFIRMED** `src/config.mjs`, CLI and synthetic tests. Frontend page checks `caseRemark.trim().length < 10`; this app additionally caps at 200. Default is “在校外旅游会注意自己安全，导员放心”, keyword 旅游, type OUTSIDE | Default is user-selected. Current active option is resolved dynamically before submission; no claim that this default was live-submitted by the new port |
| Unknown/over-limit location accuracy fails closed; default maximum is 200 m | **CONFIRMED** config and runner tests | Provider accuracy is trusted as reported; desktop location may be unavailable |
| Browser channels and installing Chromium are supported | **CONFIRMED** [Playwright browsers](https://playwright.dev/docs/browsers), pinned package metadata and browser launcher | OS dependencies and a real location provider are separate requirements |
| Windows task uses interactive current-user login and restart settings | **CONFIRMED** generated fields against [Microsoft Task Scheduler schema](https://learn.microsoft.com/en-us/windows/win32/taskschd/task-scheduler-schema): task version 1.3, InteractiveToken, LogonTrigger, RestartOnFailure; synthetic generator tests | No live Task Scheduler installation, OAuth or location validation yet; tests do not perform full XSD validation |
| Linux unit uses a desktop-session user service | **CONFIRMED** generator and [systemd service source manual](https://github.com/systemd/systemd/blob/main/man/systemd.service.xml); [desktop integration](https://github.com/systemd/systemd/blob/main/docs/DESKTOP_ENVIRONMENTS.md) scopes graphical-session.target | Desktop integration varies; no live Linux installation, OAuth or location validation yet |
| Platform data directories are application choices consistent with user-state conventions | **CONFIRMED** config and tests; [Apple user Library](https://developer.apple.com/library/archive/documentation/FileManagement/Conceptual/FileSystemProgrammingGuide/FileSystemOverview/FileSystemOverview.html), [Windows Known Folders](https://learn.microsoft.com/en-us/windows/win32/shell/knownfolderid), [XDG state directory](https://specifications.freedesktop.org/basedir/latest/) | Not a claim these are the only mandated paths |
| Shanghai scheduler supports bounded pre-submit retries and stops ambiguous submitted outcomes | **CONFIRMED** daemon/runner and offline tests, including waking after retry deadline and earliest check-in window | Sleep/shutdown and upstream outages may prevent completion; server windows are authoritative |
| CI covers Node 22/24 on Ubuntu/macOS/Windows with synthetic data only | **CONFIRMED** workflow matrix and test files | This tests code and file generation, not live native service managers, school E2E, OAuth or GPS |
| Original macOS flow succeeded on 2026-10-10 | **UNVERIFIABLE publicly**: historical private evidence is deliberately excluded | The maintainers' historical run is not evidence of the new port passing E2E |
| New portable package has live school E2E or verified Windows/Linux authentication/location | **UNVERIFIABLE / pending collaboration** | README explicitly discloses this limitation; do not infer it from offline CI |

The school frontend was fetched read-only without authentication; no school submission was performed for this audit. Sources and implementation were checked separately from writing. Future upstream changes require a fresh audit and authorized real-device validation.
